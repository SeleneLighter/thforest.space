1. 课程要研究什么

从程序设计一路向上看, 我们会依次遇到编程语言、数据结构、算法, 再到人工智能、大语言模型、密码学等更复杂的应用. 程序设计解决的是“如何把计算过程写出来”, 数据结构关心“如何组织数据”, 而算法设计与分析开始追问一个更本质的问题:

面对同一个计算任务, 怎样找到一个既正确又高效的计算过程?

这正是算法这门课的核心.

从这个角度看, 算法本身也是一种技术. 更快的硬件当然可以让程序变快, 但算法上的改进往往会带来数量级上的差异. 一个指数时间算法即使放在快很多的机器上, 可处理的输入规模通常也只会增加一点点; 而把算法从指数时间改成多项式时间, 才可能真正改变问题是否可计算.

课程的整体内容也围绕这一目标展开:

  1. 算法分析: 正确性, 最好、平均与最坏情况, 渐近记号, 排序.
  2. 算法设计技术: 分治, 递推式, 贪心, 动态规划, 摊还分析.
  3. 图算法: BFS, DFS, 最小生成树, 最短路, 最大流.
  4. 困难问题: NP 完全性与近似算法.

2. 什么是算法

算法并不是计算机出现之后才有的概念.

欧几里得算法用重复取余计算最大公因数; 刘徽的割圆术通过不断加倍正多边形边数逼近圆周率; 九世纪的花拉子米系统整理了十进制算术与解方程的机械步骤. “algorithm” 一词本身就来自花拉子米名字的拉丁化形式.

这些例子有一个共同点: 它们都把“如何得到答案”写成了一套明确、机械、可执行的步骤.

Definition 1 (算法)

算法是一个良定义的计算过程. 它接收一个或一组输入, 经过有限个明确步骤, 在有限时间内终止, 并产生一个或一组输出.

因此, 一个计算问题首先应被看成一个输入与输出之间的关系:

算法的任务, 就是对每一个合法输入, 按照固定规则得到满足问题要求的输出.

这个定义看似简单, 却已经暗含了几个关键要求:

  1. 明确性: 每一步都应当没有歧义.
  2. 机械性: 每一步都能由计算模型执行.
  3. 有限终止: 对合法输入, 计算过程最终停止.
  4. 规格: 我们必须先知道“什么输出才算正确”, 才能讨论算法正确性.

于是, 对以后遇到的每一个算法, 都可以固定地问三遍:

Tip

  1. Is it correct?

  2. How much time does it take, as a function of the input size?

  3. Can we do better?

3. 大语言模型是不是算法

一个固定的大语言模型推理过程, 从输入 token 开始, 反复执行确定的神经网络运算, 再按给定采样规则生成下一个 token. 随机性本身并不会让它“不是算法”: 随机比特可以视为额外输入, 随机算法仍然是算法.

终止问题也类似. 如果系统规定遇到停止 token 或达到最大生成长度时结束, 那么整个过程具有明确的终止规则.

真正不同的是“正确性”这一问.

传统算法问题通常有明确规格. 例如排序要求输出必须是输入元素的一个排列, 且按非递减顺序排列. 因而我们可以证明一个排序算法对所有输入都正确.

而一般性的 LLM 回复通常没有这样一个数学上唯一、可检验的输出规格. 我们可以用 benchmark 或人工评价衡量它, 却很难像证明排序算法那样证明“所有回答都正确”.

因此, LLM 推理完全可以作为计算过程研究其时间与空间代价; 但本课程主要研究的是那些具有明确规格, 因而能够进行数学正确性证明的问题.

6. RAM 计算模型

真实计算机包含缓存、流水线、主存等复杂机制. 为了得到与具体机器无关的复杂度分析, 课程采用 RAM (Random-Access Machine) 模型.

Definition 1 (RAM 模型)

RAM 模型把计算机抽象为一台顺序执行指令的随机访问机器. 访问任意一个可寻址的内存单元都视为 时间; 对一个机器字 (word) 中的数据进行基本算术、比较、赋值和分支等操作, 也视为 时间.

8. 插入排序：把新元素放进已经有序的前缀

插入排序可以类比整理手里的扑克牌.

假设左边一部分牌已经排好. 每次从右边取一张新牌 key, 从已排序部分最右端开始向左寻找位置. 所有大于 key 的元素向右移动一格, 最后把 key 放进空出来的位置.

Insertion-Sort(A, n):
    for i = 2 to n:
        key = A[i]
        j = i - 1

        while j > 0 and A[j] > key:
            A[j + 1] = A[j]
            j = j - 1

        A[j + 1] = key

这里先保存 key 非常重要. 因为后续会执行 A[j+1] = A[j], 如果不提前保存原来的 A[i], 它可能在元素右移过程中被覆盖.

而且移动必须从右向左进行. 这和在数组中为新元素“腾位置”是同一个道理.

9. 如何证明插入排序正确：循环不变式

一个程序“看起来对”, 不是证明.

对于循环算法, 最常见的证明工具是循环不变式. 它和数学归纳法本质上是同一种逻辑结构.

Definition 1 (循环不变式)

循环不变式是在循环每次迭代的某个固定位置都保持成立的命题. 证明时通常分为初始化、保持、终止三个部分.

对插入排序, 课件给出的不变式可以写得更完整一些:

  1. 已按非递减顺序排列;
  2. 恰好由原数组最初的前 个元素组成, 只是次序可能改变.

第二条很重要. “已经有序”只说明顺序对了, 还必须保证我们没有丢掉元素、复制元素或凭空产生新元素. 排序要求输出是原输入的一个排列, 因而“元素集合保持不变”也是正确性的一部分.

11. 为什么课程通常先看最坏情况

最坏情况运行时间定义为: 在所有规模为 的输入中, 算法可能达到的最长运行时间.

它受到重视主要有三个原因.

第一, 它给出一个保证. 如果我们证明最坏情况为 , 那么任何规模为 的输入都不会比这个界更坏.

第二, 某些问题中的最坏情况并不罕见. 例如线性查找一个不存在的元素, 就必须检查整个序列.

第三, 最坏情况不需要额外假设输入来自什么概率分布, 因而适合作为不同算法之间的统一比较标准.

当然, 这不意味着平均情况不重要. 后面的随机算法、QuickSort 等内容里, 平均或期望运行时间会变得非常关键. 只是那时我们必须把随机性的来源写清楚.

12. 一个可反复使用的算法分析框架

从 Fibonacci 和插入排序两个例子中, 可以提炼出一套以后反复使用的分析顺序.

Tip

第一步: 形式化问题.

先写清楚合法输入是什么, 输出必须满足什么条件.

第二步: 设计一个算法.

哪怕一开始并不快, 先得到一个明确可执行的过程.

第三步: 证明正确性.

递归算法常用归纳法; 循环算法常用循环不变式; 更复杂的算法还会使用交换论证、割性质、最优子结构等方法.

第四步: 指定计算模型.

必须知道什么操作算“一步”. RAM 模型、位复杂度模型、I/O 模型可能给出不同的复杂度表达.

第五步: 分析时间和空间.

识别输入规模, 统计关键操作次数, 并区分最好、平均、最坏情况.

第六步: 找瓶颈.

重复计算、昂贵的数据移动、过大的状态空间, 往往暗示着可以改进的地方.

13. 本节小结

读完这一部分, 最值得真正掌握的并不是几个复杂度结论, 而是下面这些判断习惯:

  1. 算法必须有明确输入、输出、步骤与终止条件.
  2. “正确”与“高效”是两个独立问题.
  3. 对每个算法都要问: 是否正确, 运行多久, 能否更好.
  4. 指数时间和多项式时间之间的差异, 通常远大于硬件常数倍加速.
  5. 复杂度依赖计算模型; 大整数运算不能无条件视为常数时间.
  6. RAM 模型把一个 位 word 上的常见基本运算视为常数时间.
  7. 插入排序正确性的核心是循环不变式, 而不变式必须同时保证“有序”和“仍是原元素的排列”.
  8. 插入排序最好情况为 , 在均匀随机排列下平均情况为 , 最坏情况也为 .
  9. 平均情况分析必须给出概率分布; 最坏情况分析则提供对所有输入有效的保证.

以后学习渐近记号、分治、动态规划或图算法时, 形式会越来越复杂, 但基本问题不会改变:

我们要设计一个什么样的计算过程, 为什么它一定正确, 它究竟付出了多少代价, 以及还有没有更好的办法?
